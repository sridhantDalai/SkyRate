## 1. Table Naming Conventions & Partitioning Strategy

The ML pipeline does **not** write to static tables (e.g., `fares` or `indices`). Instead, it dynamically generates date-partitioned tables using a daily calendar string format: `DD_MM_YYYY`.

| Table Category | Exact Naming Pattern | Example (19 Sept 2026) | Generated By | Consumed By |
| :--- | :--- | :--- | :--- | :--- |
| **Raw Scraped Fares** | `public."scraped_on_{DD_MM_YYYY}"` | `public."scraped_on_19_09_2026"` | `main_scraper.py` $\rightarrow$ `daily_pipeline.py` | `index_calculator.py`, Backend API |
| **Computed APIx Indices** | `public."index_for_{DD_MM_YYYY}"` | `public."index_for_19_09_2026"` | `index_calculator.py` $\rightarrow$ `daily_pipeline.py` | Backend API, Frontend UI |

### Partition Lifecycle Rules:
1. **Creation:** Tables are created dynamically by executing DDL via `psycopg2` direct connection on the database pool (`daily_pipeline.py:L203-234`).
2. **Same-Day Rerun Safety:** If a scrape pipeline runs more than once on the same date, the ML pipeline executes a SQL deletion:
   ```sql
   DELETE FROM public."scraped_on_{DD_MM_YYYY}" WHERE route != '__SKYRATE_NEVER_MATCH__';
   ```
   *Implication:* Same-day data is wiped and replaced with the authoritative fresh scrape; past dates are immutable and never modified.
3. **Permissions Granted by ML:**
   ```sql
   GRANT ALL ON public."scraped_on_{DD_MM_YYYY}" TO anon, authenticated, service_role;
   GRANT ALL ON public."index_for_{DD_MM_YYYY}" TO anon, authenticated, service_role;
   ```

## 2. Table Schemas: Columns, Types & Nullability

### Table A: `public."scraped_on_{DD_MM_YYYY}"`
*DDL Source:* `prototype/ML/ml/generate_sql.py:L6-19` & `prototype/ML/ml/daily_pipeline.py:L206-222`

```sql
CREATE TABLE IF NOT EXISTS public."scraped_on_{DD_MM_YYYY}" (
    "ID"           TEXT,
    route          TEXT,
    carrier        TEXT,
    flight_number  TEXT,
    is_non_stop    BOOLEAN,
    t_window       TEXT,
    base_fare      NUMERIC,
    taxes          NUMERIC,
    udf_fee        NUMERIC,
    gross_fare     NUMERIC,
    status         TEXT,
    source         TEXT
);
```

#### Detailed Column Contract

| Column Name | SQL Type | Python / JSON Type | DDL Nullable? | Runtime Nullable? | Meaning & Valid Values |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `"ID"` | `TEXT` | `str` | Yes (no `NOT NULL`) | **No** | 8-character lowercase hexadecimal unique record identifier generated via `uuid.uuid4().hex[:8]`. Note: Quotation marks are mandatory in raw SQL queries (`"ID"`). |
| `route` | `TEXT` | `str` | Yes | **No** | 3-letter IATA departure and arrival airport codes separated by a single hyphen (e.g. `"DEL-BOM"`, `"BLR-DEL"`, `"BOM-GOI"`). Always uppercase. |
| `carrier` | `TEXT` | `str` | Yes | **No** | Full commercial airline name (e.g., `"IndiGo"`, `"Air India"`, `"SpiceJet"`, `"Akasa Air"`) or carrier code fallback. |
| `flight_number` | `TEXT` | `str` | Yes | **No** | Flight designator with carrier prefix (e.g., `"6E-204"`, `"AI-805"`, `"SG-8169"`) or `"Unknown"`. |
| `is_non_stop` | `BOOLEAN` | `bool` | Yes | **No** | `true` if flight has zero intermediate stops (`len(legs) == 1`); `false` if connecting. |
| `t_window` | `TEXT` | `str` | Yes | **No** | Advance-purchase time horizon window string. Permitted values: `"T"`, `"T+1"`, `"T+7"`, `"T+15"`, `"T+30"`, `"T+45"`. |
| `base_fare` | `NUMERIC` | `float \| None` | Yes | **Yes** | Net airline ticket price. **`NULL` (`NaN`) when `status` is `"Sold Out / Cancelled"`**. |
| `taxes` | `NUMERIC` | `float \| None` | Yes | **Yes** | Government taxes, fees, and surcharges **with airport UDF fee subtracted**: $\max(0.0, \text{raw\_tax} - \text{udf\_fee})$. **`NULL` when `status` is `"Sold Out / Cancelled"`**. |
| `udf_fee` | `NUMERIC` | `float \| None` | Yes | **No** | Airport User Development Fee based on origin airport (e.g. DEL: 77.0, BOM: 120.0, BLR: 250.0). Always populated even for cancelled flights. |
| `gross_fare` | `NUMERIC` | `float \| None` | Yes | **Yes** | Total final fare paid by traveler ($\text{base\_fare} + \text{taxes} + \text{udf\_fee}$). **`NULL` when `status` is `"Sold Out / Cancelled"`**. |
| `status` | `TEXT` | `str` | Yes | **No** | Inventory status. Permitted values: `"Available"`, `"Sold Out"`, or `"Sold Out / Cancelled"`. |
| `source` | `TEXT` | `str` | Yes | **No** | Extraction channel (e.g., `"EaseMyTrip"`, `"Multiple (Cleartrip)"`, `"Analytics Engine"`). |

## 3. Structural Fields Discrepancies (Pydantic Model vs SQL DDL)

Comparing [`prototype/ML/models.py`](file:///c:/Users/mkrma/Desktop/SkyRate/prototype/ML/models.py) with the actual PostgreSQL DDL in `daily_pipeline.py`:

```python
# prototype/ML/models.py:L5-20
class FarePayload(BaseModel):
  ID: str
  route: str
  carrier: str
  flight_number: str
  is_non_stop: bool
  t_window: str
  base_fare: Optional[float] = None
  taxes: Optional[float] = None
  udf_fee: Optional[float] = None
  convenience_fee: Optional[float] = None  # <-- EXCLUDED FROM SQL
  gross_fare: Optional[float] = None
  status: str = Field(default="Available")
  source: str
  extracted_at: datetime = Field(
      default_factory=datetime.now
  )  # <-- EXCLUDED FROM SQL
```

1. **`convenience_fee`:** Exists in Pydantic `FarePayload`, but **IS EXPLICITLY DROPPED** before SQL insertion (`data_processor.py:L82-83`: `df = df.drop(columns=['convenience_fee'])`). It is **NOT** present in the Supabase table.
2. **`extracted_at`:** Exists in Pydantic `FarePayload`, but **IS NEVER WRITTEN** to the SQL table. The timestamp is represented entirely by the table name date suffix (`scraped_on_DD_MM_YYYY`).
3. **`departure_time`:** Handled as internal metadata during interim scraping, but **IS NOT STORED** in the database table (`UNKNOWN` in SQL).

## 4. Primary and Unique Identifiers

* **Table `"scraped_on_{DD_MM_YYYY}"`:**
  * **Primary Key in DDL:** **NONE** (No `PRIMARY KEY` or `UNIQUE` constraint is declared in PostgreSQL DDL).
  * **Logical Identifier:** The `"ID"` column contains an 8-character hex string (`uuid.uuid4().hex[:8]`). However, uniqueness is **NOT enforced by a database constraint**.
  * **Natural Key:** `(route, carrier, flight_number, t_window)`. Duplicate raw fare rows can exist across multiple fare classes (`lstFr`) from the same flight search.
* **Table `"index_for_{DD_MM_YYYY}"`:**
  * **Primary Key in DDL:** **NONE**.
  * **Logical Unique Key:** Composite `("State", "Time_Horizon")`. Exactly one row exists per State and Time Horizon combination.

## 5. Date & Time Semantics

1. **Table-Level Partition Date:**
   The extraction date is derived exclusively from the table name (`DD_MM_YYYY`, day-month-year):
   * Example: `scraped_on_19_09_2026` $\rightarrow$ Date of extraction: `2026-09-19`.
2. **Departure Date Representation (`t_window`):**
   No explicit `DATE` or `TIMESTAMP` column exists for flight departure in SQL. Departure date is defined relative to the extraction date:
   $$\text{Departure Date} = \text{Extraction Date} + \text{Offset Days}$$
   * `"T"` = 0 days (Same-day departure)
   * `"T+1"` = 1 day
   * `"T+7"` = 7 days
   * `"T+15"` = 15 days
   * `"T+30"` = 30 days
   * `"T+45"` = 45 days
   * `"T+60"` / `"T+90"` = 60 / 90 days (Used in Index baskets)

## 6. Route & Carrier Representation

### Route Representation:
* Format: Always uppercase, hyphen-separated 3-letter IATA codes: `"{ORIGIN}-{DESTINATION}"` (e.g., `"DEL-BOM"`, `"BLR-DEL"`, `"BOM-GOI"`).
* City mapping is defined in [`prototype/ML/city_codes.py`](file:///c:/Users/mkrma/Desktop/SkyRate/prototype/ML/city_codes.py) (e.g., `DEL` = Delhi, `BOM` = Mumbai, `BLR` = Bengaluru).
* State mapping: Fixed by [`prototype/ML/index_calculator.py:L36-52`](file:///c:/Users/mkrma/Desktop/SkyRate/prototype/ML/index_calculator.py#L36-L52) based on consumer origin:
  * `"DEL-BOM"` $\rightarrow$ `"Delhi"`
  * `"BLR-DEL"` $\rightarrow$ `"Karnataka"`
  * `"BOM-GOI"` $\rightarrow$ `"Maharashtra"`
  * `"HYD-MAA"` $\rightarrow$ `"Telangana"`
  * `"CCU-BLR"` $\rightarrow$ `"West Bengal"`
  * `"AMD-BOM"` $\rightarrow$ `"Gujarat"`
  * `"MAA-CCU"` $\rightarrow$ `"Tamil Nadu"`

### Carrier Representation:
* Stored as full commercial airline names where mapped by OTA (e.g., `"IndiGo"`, `"Air India"`).
* Flight numbers follow the carrier-code hyphen format: `"{CARRIER_CODE}-{FLIGHT_NO}"` (e.g., `"6E-204"`, `"AI-805"`).
* When scraping raw DOM from aggregators (e.g. Cleartrip), carrier defaults to `"Multiple (Cleartrip)"` with flight number `"Unknown"`.

## 7. Fare Component & Accounting Semantics

The ML data processor enforces strict additive decomposition:
$$\text{Gross Fare} = \text{Base Fare} + \text{Taxes} + \text{UDF Fee}$$

1. **`base_fare`:** The net revenue accrued to the airline.
2. **`udf_fee` (User Development Fee):** Mandated by MoSPI to be decoupled. Mapped by departure airport rate:
   * `DEL`: ₹77
   * `BOM`: ₹120
   * `BLR`: ₹250
   * `HYD`: ₹281
   * `CCU`: ₹150
   * `MAA`: ₹100
   * `GOI`: ₹80
   * `PNQ`: ₹50
   * `AMD`: ₹110
   * `SXR`: ₹0
   * `COK`: ₹170
   * `JAI`: ₹150
   * Unlisted fallback: ₹100
3. **`taxes`:** Total OTA-reported taxes minus the UDF fee: $\text{taxes} = \max(0, \text{raw\_taxes} - \text{udf\_fee})$.
4. **Cancelled / Sold Out Fares:** When a flight is sold out or cancelled, `gross_fare`, `base_fare`, and `taxes` are `NULL` (`NaN`). Only `udf_fee` and `status = "Sold Out / Cancelled"` are populated.

## 8. Index Output Semantics (APIx Mathematical Formulation)

In `prototype/ML/index_calculator.py`:
1. **Anomaly Filtering:** `IsolationForest(contamination=0.01)` on `gross_fare` filters extreme price glitches before index computation.
2. **Median Aggregation:** Prices per route-horizon basket use **Median** ($P_t = \text{median}(\text{gross\_fare})$) to prevent business class tickets from skewing the consumer basket.
3. **Weighting Vectors:**
   * $P_0$: 2024 historical calibrated route prices (`BASE_PRICES_2024`).
   * $Q_0$: 2024 DGCA passenger traffic volume (`DGCA_TRAFFIC["Q0"]`).
   * $Q_t$: Current 2026 DGCA passenger traffic volume (`DGCA_TRAFFIC["Qt"]`).
4. **Formula:**
   * Laspeyres Index: $L = \frac{\sum (P_t \times Q_0)}{\sum (P_0 \times Q_0)}$
   * Paasche Index: $P = \frac{\sum (P_t \times Q_t)}{\sum (P_0 \times Q_t)}$
   * Fisher Ideal Index: $F = \sqrt{L \times P}$
   * RealTime APIx: $\text{RealTime\_APIx} = \text{MoSPI\_Base} \times F$
   * Basket Inflation: $\text{Basket\_Inflation} = (F - 1) \times 100\%$

## 9. Security & API Exposure Policy

### Columns Safe for Public API Exposure:
* **From Scraped Fares:** `"ID"`, `route`, `carrier`, `flight_number`, `is_non_stop`, `t_window`, `base_fare`, `taxes`, `udf_fee`, `gross_fare`, `status`.
* **From Indices:** `"State"`, `"Time_Horizon"`, `"MoSPI_Base"`, `"Basket_Inflation"`, `"RealTime_APIx"`.

### Columns/Data That MUST NOT Be Publicly Exposed:
1. **`source` Column:** Storing the specific OTA or airline scraped (e.g. `"EaseMyTrip"`, `"Scrape.do API"`). Exposing external OTA identifiers in consumer-facing APIs introduces legal and scraping detection risks. The backend API must mask or sanitize this to `"Aggregated Airline Data"` or `"SkyRate Network"`.
2. **Database Credentials & Connection Strings:** `SUPABASE_DB_URL`, `SUPABASE_SECRET_KEY`, and Postgres connection strings.
3. **Scraper Proxy Credentials:** Internal proxy credentials in `proxy_manager.py`.

## 10. Pagination & Empty-Data Behaviour

### Pagination Requirements:
* Both Supabase PostgREST and the backend API require limit/offset range pagination.
* PostgREST requires `.range(offset, offset + limit - 1)`.
* Maximum recommended query batch size: **1,000 rows** (as implemented in `index_calculator.py:L311`).
* Maximum public API query batch size: **200 rows** (enforced by `FareFilterQuery: limit <= 200`).

### Expected Empty-Data Behaviour:
1. **Partition Table Missing:** If `scraped_on_{today}` has not been created yet by the scheduled 02:17 AM pipeline, the backend **must not** return a 500 error. It must probe backwards up to 7 days ($T-1, T-2, \dots$) to locate the most recent populated partition.
2. **Empty Partition Table (0 rows):** In `index_calculator.py:L303-306`, a 0-row table aborts with `exit(1)`. In the backend API, a 0-row partition must return `{"success": true, "data": {"items": [], "total_count": 0}}`.
3. **Missing State in Index:** Returns HTTP 404 with structured error envelope `ResourceNotFoundException`.
4. **Offline / Unconfigured Supabase:** Backend falls back cleanly to static file artifacts `prototype/ML/api_output.json` and `prototype/ML/macro_indicators_db.json`.

## 11. Unknowns & Unenforced Attributes

As mandated, where schemas or constraints are absent from the ML codebase:
* **Foreign Keys:** `UNKNOWN` / None exist. There are no relational foreign key constraints between `scraped_on` and `index_for`.
* **Indexes / Indices in SQL:** `UNKNOWN` / None exist. No `CREATE INDEX` statements exist in `generate_sql.py` or `daily_pipeline.py`.
* **Flight Departure Time:** `UNKNOWN` in SQL. Departure clock times (e.g. `14:30`) are not stored in the database.
* **Return Dates:** `UNKNOWN` in SQL. All scraped data is strictly one-way (`tripType=O`).
